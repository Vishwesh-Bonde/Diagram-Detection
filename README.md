# AI-Based Diagram Detection

A simple, reproducible web application that detects and visualizes diagrams
(figures, images, charts and graphs) inside document images using
**PaddleOCR's PP-DocLayout-L** layout-detection model.

Upload a document page, run detection, and view/download the original image
with the detected diagram regions outlined by bounding boxes.

---

## Overview

Document pages often mix text, tables, headers and figures. This project uses a
pretrained document-layout model to locate diagram-like regions and highlight
them directly on the page. It is intended as a clear, beginner-friendly
demonstration of applying a pretrained layout model behind a lightweight
Streamlit interface.

The application runs entirely locally on CPU. The detection model is downloaded
automatically the first time it is used.

## Problem Statement

Manually locating diagrams within scanned documents or multi-page reports is
slow and error-prone. This project automates the first step: identifying which
regions of a page correspond to diagrams/figures so they can be reviewed,
extracted, or highlighted without scanning the whole page by hand.

## Objectives

- Use a pretrained document-layout model (PP-DocLayout-L) without training or
  modifying it.
- Provide a simple web UI to upload an image, run detection, and inspect the
  result.
- Draw detected diagram regions on the original image and allow the annotated
  result to be downloaded.
- Keep the detection pipeline small, readable and reproducible from a fresh
  clone.

## Main Features

- Upload JPG, JPEG or PNG document images.
- Validate the uploaded image before running inference.
- Run detection only on demand with a `Detect Diagrams` button.
- Display the original image with actual model bounding boxes drawn on it.
- Show the number of diagram regions and the model's label/confidence values
  when available.
- Friendly message when no diagrams are found.
- Download the annotated result image as `diagram_detection_result.png`.
- The model is cached so repeat interactions do not reload it.

## Setup (Windows PowerShell)

Create and activate a virtual environment, then install dependencies:

```powershell
py -3.12 -m venv venv
.\venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

> **PaddlePaddle note:** `paddlepaddle==3.2.2` is the verified CPU build for this
> project on Windows/Python 3.12. The plain package name installs the CPU
> build. If you require GPU inference, install the CUDA build that matches your
> system from the official PaddlePaddle installation guide instead, then verify
> that `paddleocr` still runs.

## Model Download

No manual download is normally required. On the first detection run, PaddleOCR
downloads **PP-DocLayout-L** into the PaddleX cache:

```
%USERPROFILE%\.paddlex\official_models\PP-DocLayout-L
```

The model is cached and reused on later runs. If you need to force a
re-download, delete that folder manually and run the app again. The model files
are intentionally excluded from Git.

To pre-download without launching the UI, run:

```powershell
python test_detection.py
```

## Running the Application

With the virtual environment activated:

```powershell
streamlit run app.py
```

Streamlit opens the app in your browser (by default at
`http://localhost:8501`).

### Using the app

1. Click the upload area and choose a JPG, JPEG or PNG document image.
2. Review the uploaded image shown on the page.
3. Click **Detect Diagrams**.
4. View the annotated result (bounding boxes drawn on the original image),
   the number of detected diagram regions, and the detection details.
5. Click **Download Result Image** to save `diagram_detection_result.png`.
6. To try another image, upload a new file and click **Detect Diagrams** again.

To run the detection from the command line instead of the UI:

```powershell
python test_detection.py
```

This reads `answer_sheet.jpg` and writes the annotated result to
`output_image.png`.

## Known Limitations

- Detection quality depends entirely on the pretrained PP-DocLayout-L model. It
  can miss diagrams, or label non-diagram regions incorrectly.
- Only a subset of layout labels (`image`, `figure`, `chart`, `graph`) is treated
  as a "diagram"; other layout categories are ignored by design.
- This is layout detection only. No text recognition (OCR) is performed, and no
  cropped images of individual diagrams are produced.
- CPU inference can be slow on large images and the first run also includes the
  one-time model download.
- Results are not claimed to be accurate or scientifically validated; they are a
  practical demonstration of the model.
